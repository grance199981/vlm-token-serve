# 补充实验 S1–S4 结果（2026-10-25 完成）

在 2×L40 48GB 服务器上运行（第 2 次启动；第 1 次因 GPU0 上出现其他任务而作废），插件 0.1.6，GPU0，服务器时间 03:33–08:58。5 个阶段全部 rc=0；52 个 serving / K1 服务 0 失败请求、前缀和 MM 缓存命中都是 0%；运行期间 GPU0 干扰监控没有报警。方案和预注册判据见 `docs/plans/FOLLOWUP_PLAN.md`（写于运行之前；S2 的 R_pred 式子在正式运行前更正过）。汇总：`experiments/w6/followups_summary.py`，结果 JSON 在运行目录的 `followups_summary.json`。

## 0. 一句话

| 实验 | 结论 |
|---|---|
| **S1 记账模型换条件** | **预测在两个新条件下都成立**：8 个格子的实测 ÷ 预测在 0.937–1.064 之间；结构差距随条件变化的方向也和预测一致（保留 25% 时差距扩大到 48%，1344 图时缩小到 24%） |
| **S2 FP8 的 Amdahl 解释** | Qwen3-VL 上 Amdahl 比例完全解释了叠加小于相乘（预测 R 0.920，实测 0.922）；Qwen3.5 上只解释了一部分（0.894 对 0.856）。另外，serving 时一次 ViT 调用只处理 2–2.5 张图，W5c 的"批处理摊薄"推断不成立；但 FP8 的 ViT 在 serving 中每张图反而快 7–10% |
| **S3 进程历史效应** | 关掉前缀缓存后效应消失（+2.2 ms），开着时复现（+13.6 ms），所以这个效应和前缀缓存有关 |

## 1. S1：K1 记账模型换条件再测

设置同 W4 K1（4 GiB KV 预算、每个请求 2 张图、输出 256、max_num_seqs 128），并发 128，3 次重复。B0 的稳态运行并发和 W4 K1 一致（896 图：Qwen3-VL 15.36 对 15.38，Qwen3.5 33.51 对 33.51），说明设置可复现。实际 prompt 长度和预测用的完全一致（例如 1344 图 B0 3604 / 3608，裁剪 1840 / 1844，降分辨率 1876 / 1880）。

|---|---|---|---|---|---|---|---|---|

| S1b 保留 50%，1344 | Qwen3-VL | 随机 | 6.89 | 13.76 | 1.997 [1.992, 2.001] | 1.893 | 1.055 | 0.92 |

| 假设 | 判据 | 实测 | 结论 |
|---|---|---|---|
| **H-S1a** 记账模型在新条件下仍准 | 8 格实测 ÷ 预测都在 [0.85, 1.15] | 0.937–1.064 | **成立** |
| **H-S1b** 结构差距随条件变化 | S1a ≥ 40%；S1b 在 [10%, 30%] | S1a 48.3%（降分辨率 50.0%）；S1b 23.8%（降分辨率 28.8%） | **成立** |
| **H-S1c** 降分辨率和裁剪的并发增益相同 | 相差 ≤ 10% | 3.8%、0.6%、1.0%、7.6% | **成立** |

读法：
1. 同一个只用 B0 标定的记账模型，在保留率减半、图片面积变成 2.25 倍的条件下都没有失准。"混合注意力的 KV 收益比全注意力小"不是保留 50%、896 图这一个点上的巧合，而是可以事先算出来的。
2. 结构差距的大小取决于条件：视觉 token 占比越高（1344 图），混合模型能省下的比例越大，差距越小（24%）；省得越狠（保留 25%），全注意力的增益涨得更快，差距越大（48%）。
3. 和 W4 K1 不同的一点：1344 图时全注意力的实测比预测高 5–6%（K1 是低 1–4%）。B0 只有约 7 个请求同时运行，并发值是小整数附近的平均，粒度误差变大，这是合理推断，没有验证。
4. Qwen3.5 降分辨率在 1344 图时比裁剪低 7.6%（30.86 对 33.37），而它的 prompt 只多 36 个 token。备选解释（推断）：混合模型按 528 个 token 一块分配 KV，降分辨率配置在 decode 后段越过一个块边界，裁剪配置没有越过。 **（2026-10-25 更新：这个推断撤回。T5 检验了另一个机制并成立：准入时只要求 prompt 装得下，生成中跨块时触发抢占；降分辨率抢占 183 次，裁剪 30 次。见 `FOLLOWUP2_RESULTS.md` §5。）**

## 2. S2：FP8 叠加小于相乘的 Amdahl 解释

P 负载（4 张 896 图、输出 32），预算 2048，并发 64，打开 ViT 追踪，1 次。T = 每个请求的时间（1 / 吞吐），V = 每个请求的 ViT 时间（测量窗口内 ViT 总耗时 ÷ 完成的请求数）。追踪会让吞吐略降（B0：1.965 对不追踪的 1.992 req/s）。

| 模型 | 配置 | req/s | T（ms/请求） | ViT（ms/请求） | ViT 占比 | 每次 ViT 调用的图片数 | 每张图的 ViT 时间（ms） |
|---|---|---|---|---|---|---|---|
| Qwen3-VL | B0 bf16 | 1.965 | 509.0 | 145.8 | 0.286 | 2.5 | 36.45 |
| | B0 全量 FP8 | 2.838 | 352.4 | 135.4 | 0.384 | 2.5 | 33.86 |
| | B0 只量化 LLM | 2.723 | 367.3 | 127.7 | 0.348 | 2.5 | 31.91 |
| | RATE bf16 | 3.134 | 319.1 | 138.5 | 0.434 | 4.9 | 34.61 |
| | RATE 全量 FP8 | 4.117 | 242.9 | 131.2 | 0.540 | 4.9 | 32.80 |
| | RATE 只量化 LLM | 4.005 | 249.7 | 131.1 | 0.525 | 4.9 | 32.78 |
| Qwen3.5 | B0 bf16 | 2.091 | 478.3 | 145.1 | 0.303 | 2.0 | 36.28 |
| | B0 全量 FP8 | 3.238 | 308.8 | 131.2 | 0.425 | 2.0 | 32.80 |
| | B0 只量化 LLM | 3.146 | 317.9 | 117.0 | 0.368 | 2.0 | 29.25 |
| | RATE bf16 | 3.321 | 301.1 | 133.1 | 0.442 | 4.0 | 33.27 |
| | RATE 全量 FP8 | 4.325 | 231.2 | 129.3 | 0.559 | 4.0 | 32.33 |
| | RATE 只量化 LLM | 4.280 | 233.7 | 122.4 | 0.524 | 4.0 | 30.61 |

**Amdahl 预测**（只量化 LLM；LLM 部分的加速倍数 s 取自 B0，假设对 RATE 配置一样）：

| 模型 | s（LLM 部分加速） | FP8 对 RATE 配置的加速：预测 / 实测 | R：预测 / 实测（追踪运行） | W5c 不追踪的 R |
|---|---|---|---|---|
| Qwen3-VL | 1.516 | 1.275 / 1.278 | **0.920 / 0.922** | 0.923 |
| Qwen3.5 | 1.659 | 1.346 / 1.289 | **0.894 / 0.856** | 0.872 |

| 假设 | 判据 | 实测 | 结论 |
|---|---|---|---|
| **H-S2a** 一次 ViT 调用处理多个请求 | 并发 64 时每次调用 ≥ 8 张图（B0 bf16） | 2.5 / 2.0 张 | **证伪** |
| **H-S2b** 批处理下 FP8 的 ViT 不慢 | 全量 FP8 每张图 ≤ bf16 的 1.05 倍（B0） | 0.93 / 0.90 倍 | **成立** |
| **H-S2c** Amdahl 能解释只量化 LLM 时的 R | \|R_pred − R_实测\| ≤ 0.03 | Qwen3-VL 0.002；Qwen3.5 **0.038** | **部分证伪**（Qwen3.5 超出） |

读法：
1. **Qwen3-VL 上，叠加小于相乘完全是 Amdahl 比例造成的**：FP8 只把非 ViT 部分加速 1.52 倍，裁剪后 ViT 占比从 29% 升到 43%，按比例算出来的 R（0.920）和实测（0.922）几乎相同。
2. **Qwen3.5 上还有别的原因**：实测 R 比 Amdahl 预测低 0.04，也就是 RATE 配置的非 ViT 部分被 FP8 加速得比 B0 少。备选解释（推断，未验证）：裁剪后序列变短，LLM 里不被 FP8 加速的部分（线性注意力层的递推、每个请求固定的调度和采样开销）占比更大。
3. **W5c 的"批处理摊薄"推断被否定**：serving 时每次 ViT 调用只有 2–2.5 张图（B0），RATE 配置是 4–4.9 张；合理推断是每步 2048 个 token 的预算一次只够调度约半个 B0 请求的图片（未单独验证）。但 FP8 的 ViT 在 serving 中每张图反而快 7–10%，和单请求计时里"FP8 的 ViT 慢 10–13%"相反，原因没有查清。所以 W5c 里"让 FP8 跳过 ViT 会让不压缩的配置变慢"有了直接证据（serving 中 FP8 的 ViT 本来就更快），但为什么单请求时更慢仍是未知。 **（2026-10-25 更新：T2 显示，serving 并发 1 时 FP8 的 ViT 仍慢 17–72%，所以"单请求时更慢"不是计时环境造成的；高并发时变慢的是 bf16 的 ViT，FP8 基本不变。见 `FOLLOWUP2_RESULTS.md` §2。）**
4. serving 中 bf16 每张图的 ViT 时间（36 ms）比单请求时（4 张图一次 109 ms，约 27 ms/张）高约 33%，可能是每次调用图片更少、固定开销摊得更差（推断）。

## 3. S3：Qwen3.5 的进程历史效应

Qwen3.5 B0，单图请求（D 形）的 LLM prefill 时间，每个进程 20 次中位数，各 2 个进程。

| 前缀缓存 | 只跑 D | 先 P 后 D | 差（中位数） |
|---|---|---|---|
| 关 | 63.0、63.9 ms | 65.9、65.3 ms | **+2.2 ms** |
| 开（阳性对照） | 75.8、75.5 ms | 89.1、89.4 ms | **+13.6 ms** |

| 假设 | 判据 | 实测 | 结论 |
|---|---|---|---|
| **H-S3a** 阳性对照：缓存开时复现 | ≥ 8 ms | +13.6 ms（W4 ⑥c 是 +13.7） | **成立** |
| **H-S3b** 缓存关时消失 | ≤ 3 ms | +2.2 ms | **成立** |

结论：这个进程历史效应和前缀缓存有关，关掉缓存后基本消失。开着缓存时 D 形 prefill 本身也慢约 12 ms（75.5 对 63.5），这是 W4 ⑥ 发现的 align 模式多一步。具体是缓存里留下的哪部分状态（Mamba 状态块还是 KV 块的分配方式）造成的，这次没有分开。 **（2026-10-25 更新：T4 里在 P 和 D 之间清空前缀缓存，效应仍在（+34.1 对 +35.4 ms），所以它来自缓存内容以外的状态；而且这次幅度约为上次的 2.5 倍。见 `FOLLOWUP2_RESULTS.md` §4。）**

## 4. S4：B0 在并发 64 时比并发 32 还慢

B0，P 负载，预算 2048，2 次重复；同时追踪 ViT 和采样调度指标。

| 模型 | 并发 | req/s（2 次） | 每个请求编码的图片数 | 稳态运行中 | 稳态等待 | KV 占用 | 抢占 |
|---|---|---|---|---|---|---|---|
| Qwen3-VL | 32 | 1.964、1.965 | 4.000 | 21.2 | 9.5 | 0.32 | 0 |
| | 48 | 1.850、1.865 | 4.000 | 21.2 | 25.6 | 0.32 | 0 |
| | 64 | 1.843、1.833 | 4.000 | 21.2 | 40.9 | 0.32 | 0 |
| | 96 | 1.813、1.820 | 4.000 | 21.2 | 67.3 | 0.32 | 0 |
| Qwen3.5 | 32 | 2.094、2.121 | 4.000 | 17.0 | 14.0 | 0.10 | 0 |
| | 48 | 1.989、2.017 | 4.000 | 17.0 | 30.0 | 0.10 | 0 |
| | 64 | 1.990、1.955 | 4.000 | 17.0 | 45.0 | 0.10 | 0 |
| | 96 | 1.945、1.935 | 4.000 | 17.0 | 71.1 | 0.10 | 0 |

| 假设 | 判据 | 实测 | 结论 |
|---|---|---|---|
| **H-S4a** 现象复现 | 并发 64 的吞吐低于并发 32（两个模型、2 次） | Qwen3-VL 1.84 对 1.96；Qwen3.5 1.97 对 2.11 | **成立** |
| **H-S4b** 重复编码 | 每个请求编码的图片数，并发 64 比 32 多 ≥ 5% | 都是 4.000 | **证伪** |

读法（探索性，H-S4b 证伪后不下因果结论）：
1. 没有重复编码，也没有抢占，KV 只用了 10–32%。
2. **稳态运行中的请求数在各档并发下完全不变**（Qwen3-VL 21.2，Qwen3.5 17.0），多出来的请求只是在排队。也就是说，GPU 上的工作量在并发 32 以上就不再增加，吞吐却随排队长度单调下降（32 → 96 降 6–8%）。
3. 备选解释（推断，未验证）：随等待队列变长而增加的 CPU 开销，例如调度器每一步都要扫描等待队列、检查编码器预算，或者 API 进程同时处理更多排队请求的图片预处理。要分开，需要在不同并发下对调度器每一步的 CPU 时间计时。 **（2026-10-25 更新：T1 的引擎步追踪否定了这个备选解释：CPU 部分每步约 1.2 ms，三档并发下不变；吞吐下降的 65–75% 来自每步 GPU 执行时间变长。见 `FOLLOWUP2_RESULTS.md` §1。）**
4. 运行中的请求数被卡在约 17–21 的原因，这次也没有查（不是 KV、不是 max_num_seqs）。

## 5. 对已有结论的影响

| 已有结论 | 影响 |
|---|---|
| W4 K1："混合注意力的 KV 收益只有全注意力的约七成" | **加强**：同一个记账模型在两个新条件下预测准确（误差 ≤ 6.4%），差距大小随条件可预测地变化（24%–50%）。README 里应改成"差距大小可以事先算出来"，而不是固定的"约七成" |
| W5(b)/W5c：裁剪 + FP8 小于相乘 | Qwen3-VL 上**定位到 Amdahl 比例**；Qwen3.5 上还有约 0.04 没解释 |
| W5c："serving 时批处理摊薄 FP8 的量化开销" | **否定**：一次 ViT 调用只有 2–2.5 张图；但 serving 中 FP8 的 ViT 确实不慢（快 7–10%），原因未知 |
| W4 ⑥c：Qwen3.5 的进程历史效应 | 定位到**和前缀缓存有关**（关掉后消失） |
| W4 ③：裁剪的实测增益超过预测上界（B0 在并发 64 时变慢） | 不是重复编码；B0 吞吐随排队长度下降，运行中的请求数不变，原因仍未知 |
