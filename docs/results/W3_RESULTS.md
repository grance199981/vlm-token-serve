## 4c. 原始 RATE 重测（R 批，2026-10-23 19:04–20:11，GPU0）

**背景**：W3 和 W4 里的"修正版 RATE"（`rate`）是我们对 PR #60963 排序 bug 的降序修法。PR 作者 10-22 的修复（head `45333ba`）保留升序、只在 `denom == 0` 时退化，等价于他的原始实现，和我们的降序变体**不等价**（见 [PR #60963 的讨论](https://github.com/vllm-project/vllm/pull/60963#issuecomment-6321576342)）。10-23 只在 3 个 OCR 任务、保留 50% / 25%、两个模型上重测原始版。

**做法**：插件 0.1.3 新增 `rate_orig`，逐行照抄 PR head 的 `rate.py`。`tests/test_vts_rate_orig.py` 把 125 个用例的保留掩码和 PR 原文件逐个比较，全部一致；负对照：降序变体和前缀在每个用例上都和它不同。和 PR 一样在去掉位置通道后的整行特征上打分，所以**在 Qwen3-VL 上，原始版和降序变体有 3 处不同**：排序方向（每桶代表取最小还是最大）、投影种子、打分维度（原始版含 DeepStack 的 4 × 2560 列，降序变体只用前 2560 列）。**在 Qwen3.5 上只有前 2 处不同**。运行时4 个配置都有效（0 失败、0 OOM、插件行数 5），B0 和样本集合同 A / B 批（ChartQA 全部 2500 条，TextVQA 前 1500 条，DocVQA 前 1000 条），按 doc_id 配对 bootstrap。

### 4c.3 局限

- **RATE 的随机投影只测了一个种子**（原始版是固定种子，降序变体用 seed 0）。W3 测过随机方法的 seed 离散度（ChartQA 3 个 seed 极差 4–5 分），RATE 投影种子带来的离散度没有测过，所以原始版和降序变体之间 2–4 分的差别可能部分来自种子，Qwen3-VL ChartQA 9 分的差别大概率不只是种子（推断）。**补测了 Qwen3-VL ChartQA 50% 上的种子离散度：同一种变体换 4 种投影，Δ 的极差 2.6–6.6 分（§4d）**，所以 2–4 分的差别确实可能只是种子；9 分的差别主要来自打分列。
- 只重测了 3 个 OCR 任务和两档保留率，12.5% 和 MME / MMBench 没有重测。
- W4 ⑤ 的吞吐用的是降序变体；原始版的选择算法相同、只是 Qwen3-VL 上打分维度大 4 倍，吞吐没有单独测。

## 4d. RATE 拆分（X 批，2026-10-24，GPU0）

**问题**：§4c 里 Qwen3-VL ChartQA 保留 50% 时，原始 RATE 比降序变体差 9 分（−20.9 对 −11.9）。两者有 3 处不同，这里逐个拆开，并测 RATE 投影种子的离散度。

**做法**：用一个消融开关（内部插件 0.1.4 的 `rate_abl`，本仓库的插件没有收入这个开关）把 3 处差别做成独立选项：
- 排序方向：升序（PR，每个桶取分数最低的 token 当代表）/ 降序（我们的修法，取最高）；
- 打分列：整行（PR，Qwen3-VL 上含 3 层 DeepStack，共 4 × 2560 列）/ 只用主输出（前 2560 列）；
- 投影：PR 的固定种子投影 / 我们的生成方式加 seed 0、1、2。

两个端点组合和已有方法逐个比对过：升序 + 整行 + PR 投影 = 原始 RATE（和 PR 原文件的保留掩码一致）；降序 + 主输出 + seed 0 = 降序变体。2 × 2 × 4 = 16 个配置，只跑 Qwen3-VL、ChartQA 全部 2500 条，16 个配置都有效（0 失败、0 OOM）。B0 同 §4c，按 doc_id 配对 bootstrap。

### 4d.3 结论

1. **§4c 里 9 分的差距，主要来自"在哪些列上打分"**：在含 DeepStack 的整行上打分比只用主输出差 7.9 分；排序方向（升序还是降序）几乎没有影响（+0.4，CI 跨 0）。PR 作者的升序写法和我们的降序修法在精度上等价，前提是打分列相同。
2. **RATE 投影种子的离散度不小**：同一种变体换投影，ChartQA Δ 的极差 2.6–6.6 分。每个配置只跑了一次，所以这个极差里也含同配置重跑的波动（约 1–2 分），纯种子离散度没有单独测。单次运行的总波动就是比较时实际面对的噪声，所以 §4c 里两种 RATE 之间 2–4 分的差别（例如 Qwen3.5 上的 ChartQA / DocVQA）不能当作真实差别，只有 9 分这一处超出了这个范围。
3. 我们最初只用主输出打分，是为了避免 OOM（W3 A 批），结果在 Qwen3-VL ChartQA 上精度也更好。
4. 边界：只测了 Qwen3-VL、ChartQA、保留 50%。§4c 里 Qwen3-VL 25% 的 DocVQA 方向相反（原始 RATE −18.1，降序变体 −24.1），所以打分列的效应可能和任务、保留率有关，没有测。Qwen3.5 没有 DeepStack，这一项不适用。
