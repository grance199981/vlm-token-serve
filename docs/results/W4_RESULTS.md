- **吞吐增益 ≈ 并发增益 ÷ TPOT 比**，误差在 1–3% 以内（Little 定律：吞吐 = 在跑的请求数 ÷ 每个请求的停留时间，而停留时间主要是 256 × TPOT）。这是记账恒等式，本身不是发现。
- 有信息量的是 TPOT 的差别：**并发一样多的情况下，降分辨率的每步更快，裁剪更慢，DivPrune 最慢**。合理推断（未单独验证）：持续有新请求被准入，它们的 ViT（裁剪时不变，见 §1）和选择计算（DivPrune 每张图约 25 ms）插在 decode 步之间，拖慢了所有在跑请求的 TPOT。降分辨率同时把 ViT 计算减到约 40%，所以反而比 B0 快。
- 结果：**在 KV 受限的负载下，降分辨率和裁剪换来的准入并发一样，但降分辨率的吞吐增益更大**——Qwen3-VL 1.81× 对 1.43–1.62×，Qwen3.5 1.43× 对 1.12–1.26×。和 §1 的单请求结论（裁剪省不掉 ViT）方向一致，这里是在高并发下的体现。

### 3.4 其他观察

| 现象 | 数字 | 说明 |
|---|---|---|
| 同样的 KV 字节数，混合结构不压缩时就能多装一倍多 | B0 稳态并发 33.5 对 15.4（2.18×）；压缩后 42.8 对 27.2（1.57×） | 混合结构本来就省 KV，所以压缩再能省下的比例小，这正是 H-K1 的机制 |
| 压缩后抢占次数明显增多 | 并发 128：Qwen3-VL 68 → 115–138；Qwen3.5 29 → 287–311 | 准入的请求更多，decode 期间 KV 继续增长时更容易挤占；对吞吐的影响已经包含在上表里，机制没有单独验证 |
| 混合结构 B0 的 TPOT 比全注意力高 | 50.3 对 31.5 ms | 在跑的请求多一倍以上（33.5 对 15.4），每步批更大 |

### 3.5 结论

1. **"那一个发现"的核心预测成立**：同样的 KV 显存预算下，视觉 token 减半，全注意力（Qwen3-VL）的准入并发提升 1.75–1.77×，混合注意力（Qwen3.5）只有 1.27–1.28×，相对差距约 28%。事先锁定的账本模型（只用 B0 标定）预测准确到 1–4%。
2. 准入并发只取决于留下多少 token：降分辨率、随机、RATE、DivPrune 之间的差别 ≤ 1.4%。
3. 但吞吐不只看并发：裁剪的 ViT 和选择开销在高并发下会拖慢每一步，**降分辨率的吞吐增益比最好的裁剪还高 0.17–0.19（倍数之差）**。
4. 增益只在 KV 真正受限时出现：Qwen3.5 在并发 32 时 KV 只用到 68%，压缩几乎没有并发收益。
5. 边界：K1 是人为把 KV 预算压到 4 GiB 构造的场景；只测了保留 50% 一档、一种图片尺寸、4B 模型。

- Qwen3-VL 三次完全复现（±1–4 ms），说明测量方法本身是稳的。

- 区分方法：同样的条件各起 3 个进程（只跑 D ×3、P→D ×3），打开 `TRITON_PRINT_AUTOTUNING=1` 记录每个进程选中的配置。如果组内进程之间也差很多，而且和选中的配置对得上，就是 autotune；如果组内一致、组间差 17 ms，就是顺序效应。

### 5.4 结论

1. **计算受限的负载下，降分辨率的吞吐增益明显最大**：并发 64 时 1.94–2.13×，最好的裁剪（随机 / RATE）1.49–1.63×，DivPrune 1.19–1.32×。原因和 ① 一致：裁剪要先跑完整个 ViT，降分辨率连 ViT 一起省。
2. 裁剪之间的差别就是选择开销：随机和 RATE 几乎一样，DivPrune 每个请求的选择计算（4 张图约 100 ms）让它比 RATE 低 0.27–0.32×。
3. 这一负载下两种注意力结构的压缩增益相近（相差 ≤ 8.4%），和 K1 的 28% 形成对照：结构差异只在 KV 受限时才体现。
4. 把每步预算从 2048 加到 8192 不提高饱和吞吐（−6.3% 到 +4.1%），H-P3 被证伪；它改变的是 TTFT 和 TPOT 的分配。
5. 边界：合成噪声图、一种图片尺寸、保留 50% 一档、4B 模型、L40。

### 7.2 读法

| 观察 | 数字 | 说明 |
|---|---|---|
| **按 OCR 平均，降分辨率在两个模型上都支配 RATE** | 同一保留率下降分辨率吞吐更高、精度更好；RATE 25% 和降分辨率 50% 吞吐差不多（2.11× 对 2.05×，2.07× 对 2.13×），但 OCR 平均差得多（−24.4 对 −2.2，−11.4 对 −2.0） | 想要 RATE 25% 的吞吐，用降分辨率 50% 就能拿到，精度还高得多 |
| **TextVQA 上 Qwen3.5 的 RATE 50% 不被支配** | RATE 50% −0.4（CI 跨 0），降分辨率 50% −2.6，CI 不重叠；代价是吞吐 1.61× 对 2.13× | 和 W3 条件分析一致：文字覆盖面积小的图上裁剪更好。这是精度–吞吐平面上裁剪唯一占优的位置 |
| Qwen3.5 上 RATE 25% 在 TextVQA 上和降分辨率 50% 打平 | −2.8 [−4.0, −1.6] 对 −2.6 [−3.9, −1.3]，吞吐 2.07× 对 2.13× | 两者几乎重合；Qwen3-VL 上 RATE 25% 明显更差（−8.1） |
| 裁剪多裁也能换吞吐，但换得少 | RATE 50% → 25%：1.57× → 2.11×；降分辨率 50% → 25%：2.05× → 3.67× | 裁剪的 ViT 成本不变，保留率再低，ViT 那部分也省不下来 |

### 7.3 结论与边界

1. 在计算受限的负载下，**降分辨率是精度–吞吐的 Pareto 前沿**（按 OCR 平均，两个模型、两档保留率都是）。裁剪只在"文字覆盖面积小"的任务（TextVQA）上、用保留 50% 换取更高精度时，才是一个不被支配的选择，吞吐代价约 0.5×。
2. 边界：精度来自 W3（真实数据集图片，尺寸各异），吞吐来自 896×896 的合成噪声图，两者是分别测的，不是同一批请求；吞吐只测了 P 负载、每步预算 2048；RATE 是本项目的降序变体（和 PR 作者 10-22 的修复不等价，见 [PR #60963 的讨论](https://github.com/vllm-project/vllm/pull/60963#issuecomment-6321576342)）。
3. 这一节没有预注册的假设，只用作汇总。
4. 2026-10-23 补充：作者修复后的原始 RATE（`W3_RESULTS.md` §4c）在 Qwen3.5 保留 50% 时 OCR 平均 −1.5，降分辨率 50% 是 −2.0。10-24 改写：0.5 分的差在单次运行的波动以内（投影种子加重跑噪声，推断），按持平处理；吞吐上 RATE 更低（按降序变体算是 1.61× 对 2.13×，原始版没有单独测），所以按 OCR 平均前沿仍是降分辨率。Qwen3-VL 上原始版更差（−8.3），结论不变。
