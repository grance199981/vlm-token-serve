# W4.5 K2 结果：多轮带图会话的前缀缓存容量（2026-10-26 完成）

在 2×L40 48GB 服务器上运行（插件 0.1.7，GPU0，服务器时间 00:21–02:30），rc=0；180 个测量点、31872 个请求 0 失败；运行期间 GPU0 干扰监控没有报警。方案、判据和锁定的预测见 `docs/plans/K2_PLAN.md`（§5 在任何压缩配置运行之前提交）。汇总：`experiments/w6/k2_summary.py --pred`（预测由 `experiments/w6/k2_predict.py` 生成），JSON 在运行目录的 `k2_summary.json`。

## 0. 一句话

**多轮会话里，视觉 token 压缩换来的前缀缓存容量，全注意力是 1.57–1.59×，混合注意力只有 1.17–1.20×；而且混合模型上压缩会把小并发时的命中率从 53% 砍到 29%。** 原因是混合模型的前缀命中按 528 个 token 对齐：压缩后第 1–3 轮的共同前缀都不足 528，只有第 4 轮还能命中。事先锁定的记账模型把 6 个配置的 S\* 都预测在 ±11% 以内，小并发命中率预测在 ±0.2 个百分点以内。

## 1. 负载与口径（摘要）

每个会话 4 轮：第 1 轮 1 张 896×896 图加一句话，第 2–4 轮各一句追问，每轮输出 64 个 token；历史里带图和真实回复。S 个会话轮转，在途最多 8 个；KV 预算 4 GiB（Qwen3-VL 1820 块 × 16 token，Qwen3.5 248 块 × 528 token）。**命中率** = 第 2–4 轮命中的 token 数 ÷ prompt token 数（服务端返回）。**S\*** = 命中率降到 S = 8 时一半的会话数（相邻两档线性插值）。保留率 50%；每个点 2 次，下表是两次平均（两次的 S\* 差 ≤ 0.2）。

- 全注意力：S 在 32–48 之间，压缩把首字延迟从约 550–800 ms 降到约 200–250 ms（3–4×），这就是容量提升兑现成的延迟收益；S = 8 时三者相同（都命中）。

## 6. 和预期是否一致、怎么处理

1. **4 个预注册假设全部成立**，方向和机制都和事先写下的一致：混合模型的命中按 528 对齐，压缩后第 3 轮的共同前缀（约 516 个 token）差 12 个 token 够不到 528，这一点在 §5 的风险里写过，实测没有越过。
2. **不一致之处（照实记录，不追加实验）**：
   - **提升的幅度**：预测全注意力 1.71×、混合 1.04×，实测 1.57–1.59× 和 1.17–1.20×。两者的误差方向相反，都在缩小结构差距：全注意力压缩配置的容量比记账模型少约 6%（第 4 轮的台阶在 S = 40–44 之间，早于预测的 42.8），混合压缩配置的容量多约 8–11%（S = 56 时还有 14–18% 命中，预测是 0）。S\* 的判据是 ±20%，所以 H-K2b 成立，但"提升倍数"层面的误差更大（全注意力 −7% 到 −8%，混合 +12% 到 +15%），写结论时用实测值。
   - **混合 B0 的下降比记账模型平缓**：预测在 S = 28–48 是一个 35.4% 的平台、S = 56 掉到 0；实测从 S = 32 的 48.2% 一路降到 S = 48 的 26.8%，S = 56 还有 8.9%。标定时已经看到第 4 轮的台阶预测偏早（K2_PLAN §5.2），这次在细网格上更明显。合理推断（未验证）：记账模型把"每个 528 块占 4 个池块"当成定值，而实际上不同会话的 GDN 状态块在缓存里的去留不完全同步，所以容量边界是渐变的。
3. **机制的出处（2026-10-27 补注）**：混合模型前缀命中只能落在 align 模式的块边界上，这个机制已由 vllm-project/vllm#45238 报告（2026-06-11，同样是 Qwen3.5-4B、528 块，纯文本单轮共享前缀；根因是每个请求只登记最后一个块边界的 Mamba 状态）。相关：PR #50551（保留 decode 检查点，open）、Marconi（arXiv 2411.19379，MLSys 2025）。本结果不是发现这个机制，而是量化了视觉 token 压缩在多轮会话里怎样触发它。
4. 对已有结论的影响：K1 的结论（单轮、显存紧张时混合注意力的并发提升只有全注意力的约七成）在多轮前缀缓存这个场景下**同样成立，而且差距更大**（混合提升 1.17–1.20× 对全注意力 1.57–1.59×）；另外多了一条 K1 看不到的代价：小并发时混合模型的命中率反而下降。

## 7. 口径与局限

- 每个会话只有 4 轮、每轮回复 64 个 token、合成噪声图；真实会话更长，528 对齐的影响会随前缀变长而变小（推断：前缀越长，"不足一个块"的损失占比越小）。
- 只测了保留 50%；只测了一种在途并发（8）和一种 KV 预算（4 GiB）。
- 混合模型的 528 对齐是 vLLM 0.32 的 align 模式决定的；其他框架或其他 Mamba 缓存模式下结论可能不同。
- S\* 的插值依赖网格；正式网格是在标定之后、压缩运行之前改定的（K2_PLAN §3）。
