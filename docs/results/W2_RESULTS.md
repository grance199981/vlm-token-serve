# W2 结果：插件 v0.1 的正确性验证

> 2026-10-20。代码：`src/vts_plugin/`；设计：`docs/W2_PLUGIN_DESIGN.md`。

## 1. 插件内容

| 方法 | `VTS_METHOD` | 保留数 | 说明 |
|---|---|---|---|
| 走裁剪路径但不裁 | `keep_all` | N | 用于检验机制本身 |
| 随机 | `random` | max(1, ⌊N × keep⌋) | 按 (seed, N) 固定的随机图案 |
| 2×2 池化 | `pool2x2` | ⌈h/2⌉ × ⌈w/2⌉ | 位置取块左上角 |
| DivPrune | `divprune` | 同上 | 和官方实现逐项一致 |
| RATE（修正版） | `rate` | 同上 | 把 PR 的升序改成降序 |
| RATE（PR 原样） | `rate_pr` | 同上 | 实际等于"保留前缀" |

## 2. 验收结果

| 测试 | 内容 | Qwen3.5-4B | Qwen3-VL-4B | 证据 |
|---|---|---|---|---|
| T4 单元测试 | 选择算法、保留数、M-RoPE（覆盖所有分块边界） | 52/52 通过（与模型无关） | 同左 | `tests/test_vts_select.py`、`tests/test_vts_mrope.py` |
| T1a | 关闭缓存时，keep_all 和原版逐 logprob 相同 | ✅ 差值 0 | ❌ 文本 26/26 相同，最大 logprob 差 0.095 | 第 2 版集成测试 |
| D1（诊断） | keep_all 对比"原版 + vLLM 自带裁剪机制（`--video-pruning-rate`），不加载插件" | ✅ 差值 0 | ✅ 差值 0（原版对比"原版 + 自带机制"的差值也是 0.0946） | 第 3 版诊断 |
| T1b | 开着缓存时，keep_all 只在原版本身就不稳定的请求上有差异 | ✅（没有差异） | ✅（只有 req 10） | 第 2 版 |
| T1n | 负对照：随机保留 50% 后输出必须改变 | ✅ 54% 不同 | ✅ 46% 不同 | 第 2 版 |
| T2 | token 数：每个请求省下的数 = Σ(N − 保留数) | ✅ 8 种配置 × 26 个请求，全部精确相等 | ✅ 同左 | 第 2 版 |
| T3 | 分块 prefill（每步 256 token）后，文本不同的比例 | 8%（原版 8%） | 8%（原版 8%） | 第 2 版 |
| T3 | 关闭前缀缓存后，文本不同的比例 | 8%（原版 0%） | 15%（原版 4%） | 第 2 版 |
| T3 近似平局分析 | 开、关缓存造成的分岔点，两个备选 token 的 logprob 差距 | — | 4/4 是近似平局（0–0.25 nat）；原版 1/1 也是近似平局 | 第 4 版诊断 |
| 对照：真实裁剪造成的分岔 | 原版对比随机 50%（都关闭缓存） | — | 差距 0.6–16.9 nat | 第 4 版诊断 |
| D2（诊断） | 故意把图像 token 的行、列对调 | 23% 文本不同 | 38% 文本不同 | 第 3 版；keep_all 是 0%，说明重算的位置确实生效 |
| T3n | 故意把图像后的文本整体挪 7 个位置 | 8% 文本不同（≈ 噪声） | 8%（≈ 噪声） | 第 2 版：**端到端测试检测不到这个量级的位置误差** |
| T5（13 个请求） | 和 HF 参考实现交叉检验（判据：分岔点差距 ≤ max(1.0, 不裁剪时的最大差距)） | ❌ 随机 50% 的第 4 号请求差距 4.6；池化 4/13 不同（都是近似平局） | ❌ 随机 50% 的第 1 号请求差距 1.25 | 样本太小，扩大到 T5b |
| **T5b（100 个单图请求）** | "有把握的分歧"（一边概率 ≥ 0.8，另一边选中的 token 在这边概率 ≤ 0.05）：裁剪组 ≤ 不裁剪组 + 2 | ✅ 不裁剪 0 次，随机 50% 1 次（第 4 号请求，原因没查清） | ✅ 不裁剪 0 次，随机 50% 0 次 | T5b 运行 |
| T5b 诊断 | HF 故意用占位位置，再和 vLLM 插件比 | 1 次有把握的分歧（区分不出来） | **11 次**有把握的分歧（区分得很清楚） | Qwen3-VL 上，vLLM 插件和"位置正确"的参考实现一致，和"占位位置"的版本不一致，说明重算的位置确实被用上了 |

## 3. 结论

| # | 结论 | 状态 |
|---|---|---|
| 1 | 插件的计算和 vLLM 自带的裁剪机制逐位相同（D1）；保留数在所有请求上都精确（T2） | **已确认** |
| 2 | 在 Qwen3-VL 上，**只要打开 vLLM 自带的裁剪机制**（哪怕一个 token 都不裁），logprob 就会出现最大 0.095 的差，但文本不变。这是 vLLM 的行为，不是插件引入的 | **已确认**（D1）。原因推断是 `mrope_positions_factor` 从 1 变成 4，**未核实** |
| 3 | 开、关缓存或分块 prefill 造成的输出差异，都是近似平局翻转，和原版同属一类 | **已确认**（分岔点差距 ≤ 0.25 nat，真实变化 ≥ 0.6 nat） |
| 4 | 位置重算确实生效：故意对调行列能被检测出来 | **已确认**（D2） |
| 5 | 端到端测试检测不到"文本整体挪 7 个位置"这类小误差，这部分的正确性只能靠单元测试保证（单元测试覆盖了所有分块边界） | **已确认**是测试的局限 |
| 5b | 插件在裁剪时的计算，和独立的 HF 参考实现一致（Qwen3-VL：有把握的分歧 0/100；Qwen3.5：1/100） | **已确认**（T5b） |
| 5c | Qwen3.5 对图像 token 的位置不敏感：正确位置和占位位置几乎没有差别 | 现象**已观察到**；"原因是 3/4 的层是线性注意力，不用位置编码"属于**推断** |
| 6 | RATE PR #60963（head 06158cbe）的 `rate.py` 对任何输入都只保留前缀 token | **已确认**（用 PR 原样代码复现）；"作者原意是降序"属于**推断** |

## 4. 测试设计上的教训

| 版本 | 问题 | 改进 |
|---|---|---|
| 第 1 版 | 只比较文本；没有为每种扰动配对应的原版噪声基线；负对照的阈值（50%）是拍脑袋定的 | 第 2 版：改用 logprob；先关闭缓存再做精确比较；每种扰动配原版基线 |
| 第 2 版 | "共同前缀上的中位数 logprob 差"对严重错误不敏感：输出一开始就分岔时，共同前缀是空的，差值记为 0 | 改用"文本不同的比例"，再加上分岔点的近似平局分析 |
| 两版都有 | Windows 上用 Python 改写脚本时产生了 CRLF，远端 bash 跑不起来 | 改写一律按二进制写；提交前检查 `git ls-files --eol` |
