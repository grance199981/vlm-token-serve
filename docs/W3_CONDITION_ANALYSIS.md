# W3 条件分析：裁剪在什么条件下比降分辨率好（探索性）

> 2026-10-22 起草，在 K1 运行期间用 CPU 做。**性质是探索性的**：W3 的汇总结果已经看过，所以不算预注册；但假设和判读规则在看逐样本数据之前写下，写完再跑。
> 数据：W3 的逐样本日志（不需要新的 GPU 运行）+ 本地 parquet 里的原图。脚本：`experiments/w3/condition_analysis.py`。

## 1. 问题

W3 的汇总结果：OCR 平均上降分辨率在三档保留率下都排第一，但 **TextVQA 上修正版 RATE 明显更好**。为什么只有 TextVQA 例外？如果能找到一个可以观测的条件来解释这一点，就能回答"什么时候该用裁剪"。

## 2. 假设（在看逐样本数据之前写下）

| 编号 | 假设 | 机制（推测） | 预测 | 什么结果算不支持 |
|---|---|---|---|---|
| H-C1 | **图越小，裁剪越占优**：在同一个任务里，"降分辨率减 RATE"的逐样本得分差 d，随原图大小增大而增大 | 原图本来就小时，降分辨率之后剩下的像素太少，小字会糊掉；裁剪保留的是全分辨率的局部。原图很大时，降分辨率之后仍然够清楚 | 按 B0 的输入 token 数（反映处理器实际用的分辨率）把样本分成四组，d(最大组) − d(最小组) > 0。在 3 个 OCR 任务里至少 2 个成立，两个模型、保留 25% 和 12.5% 两档都看 | 多数任务里没有这个趋势，或者方向相反 |
| H-C2 | TextVQA 之所以例外，是因为它的图普遍更小 | 同 H-C1 | TextVQA 的 B0 token 数中位数明显低于 DocVQA；而且 DocVQA 里最小的那一组图，RATE 的相对表现也会变好 | DocVQA 的小图组里降分辨率仍然大幅领先，说明"图小"解释不了 |
| H-C3 | 内容越稀疏，裁剪越占优（只看 DocVQA / ChartQA） | 版面大部分是空白时，保留多样性高的 token 能集中留住有字的地方；满页都是字时，丢掉一半就一定会丢字 | 按"墨水占比"（灰度 < 200 的像素比例）分四组，墨水越少，d 越小（RATE 相对越好） | 没有趋势或方向相反 |

## 3. 方法

| 项 | 做法 |
|---|---|
| 样本 | 和 W3 相同：ChartQA test 2500、TextVQA val 前 1500、DocVQA val 前 1000；按 `doc_id` 和 parquet 的行号对齐，并逐条核对问题文本（对不上的比例 > 0.5% 就中止） |
| 比较对象 | 每个样本的得分差 d = 降分辨率得分 − RATE（修正版）得分（配对）；另外报告各方法相对 B0 的 Δ。也看 DivPrune |
| 大小变量 | 主变量：B0 时该样本的输入 token 数（同一任务里文本 token 数基本不变，所以它反映视觉 token 数）。辅助变量：原图像素数 |
| 分组 | 每个任务内部按主变量的四分位数分成 4 组 |
| 统计 | 每组 d 的均值，配对 bootstrap 95% CI（1000 次，seed 0）；趋势用 d(Q4) − d(Q1) 及其 bootstrap CI |
| 保留率 | 主要看 25% 和 12.5%（差别大，信号强）；50% 只作参考 |

## 4. 结果（2026-10-22，在 2×L40 48GB 服务器上用 CPU 跑，K1 运行期间）

运行：`experiments/w3/condition_analysis.py`，输出为 `condition_analysis.{json,txt}`。逐样本对齐检查：3 个任务 × 2 个模型都是 0 处不一致。d = 降分辨率得分 − RATE 得分，**正数表示降分辨率好，负数表示 RATE 好**。

### 4.1 先验假设的判定

| 假设 | 检验 | 结果 | 判定 |
|---|---|---|---|
| H-C1 图越小，裁剪越占优（任务内） | 3 个任务 × 2 个模型 × 2 档保留率 = 12 组，看 d(Q4) − d(Q1) 是否 > 0 | 1 组支持（TextVQA，Qwen3-VL，25%：+0.084 [+0.020, +0.145]）；6 组显著反向（DocVQA 3 组、ChartQA 3 组，−0.10 到 −0.17）；5 组不显著 | **不支持** |
| H-C2 TextVQA 例外是因为图小 | 比较各任务 B0 视觉 token 数的中位数 | TextVQA 约 795，DocVQA 约 3755，**ChartQA 约 463（最小）**，但 ChartQA 上降分辨率赢得最多 | **不支持** |
| H-C3 内容越稀疏，裁剪越占优（DocVQA / ChartQA 的墨水占比） | 8 组 | 1 组支持（DocVQA，Qwen3.5，25%）；3 组反向；4 组不显著 | **不支持** |

**检验本身的局限**：任务内部的图片大小分布很窄（TextVQA 四分位 700 / 793 / 798 个 token，DocVQA 3684–3931，ChartQA 456–468），按大小分组时，组间差别很可能主要来自数据来源之类的混杂因素，而不是分辨率本身。所以 H-C1 的"反向"结果也不能反过来解释成"图越大裁剪越好"。

## 5. 看完结果后的补充分析（只用于生成新假设，不能当证据）

三个先验假设都不成立后，剩下的明显差别是**答案所需信息在空间上的分布**：TextVQA 的答案通常来自图里一小块文字，文档和图表的信息铺满全图。用两个现成的变量粗略检验（`experiments/w3/condition_analysis_extra.py`，输出 `condition_analysis_extra.json`）。

## 6. 确认 H-C4 的三条路线：逻辑链（2026-10-22，先做 A）

| 步骤 | 内容 |
|---|---|
| 起点 | W3 汇总：降分辨率在 OCR 类任务上几乎全面领先，**只有 TextVQA 例外**（修正版 RATE 更好） |
| 第一轮解释（先写假设，再看数据） | H-C1 图越小裁剪越占优、H-C2 TextVQA 例外是因为图小、H-C3 版面越空裁剪越占优 → **全部不支持**（§4）。尤其是 ChartQA 图最小，降分辨率却赢得最多，直接否定了"图小"这个解释 |
| 第二轮（看完数据后提出） | 剩下最明显的差别是"答案需要的信息在图里有多集中"。两个现成的变量方向一致：TextVQA 里 OCR 词越少，RATE 越占优；DocVQA 里表格 / 列表类问题上 RATE 最差，图片类问题上打平（§5） → 提出 **H-C4：答案需要的文字越少、越集中，裁剪越占优；信息铺满全图时降分辨率占优** |
| 问题 | H-C4 是在同一批数据上看出来的，用这批数据验证它，会高估可信度。而且"OCR 词少"有两种可能：真的字少，或者字太小、OCR 没识别出来 |
| **A. 留出数据确认** | 回答"这个规律在没看过的数据上还成立吗"。用 TextVQA val 里 W3 没跑过的第 1500–4999 条，跑之前锁定判据（§7）。只用本地数据，成本最低。**A 不成立 → H-C4 作废**，"何时裁剪值得用"回到只有"TextVQA 这个任务"一个经验结论 |
| **B. 区分"字少"和"字小"** | 只有 A 成立才做。下载 TextVQA 的原始 OCR 标注（带文字框位置），按"文字区域总面积"和"单个字的高度"分别分组。如果起作用的是字的高度，结论就改写成"小字场景下裁剪更好"，两种表述的工程含义不同：前者看文字多少，后者看文字大小 |
| **C. 换数据集验证** | A、B 之后再考虑。用 OCRBench / ST-VQA 之类的场景文字数据集，检验 H-C4 是否只在 TextVQA 上成立。需要另外下载，工作量最大 |
| 依赖关系 | A → B → C 依次进行，前一步不成立就停 |

### 8.2 各方法相对 B0 的损失（分数点，按组）

| 模型 / 保留率 | 方法 | OCR ≤ 4 个词 | 5–16 个词 | > 16 个词 |
|---|---|---|---|---|
| Qwen3-VL，25% | 降分辨率 | −12.0 | −9.2 | −8.3 |
| Qwen3-VL，25% | RATE | **−3.8** | −5.4 | −11.9 |
| Qwen3-VL，12.5% | 降分辨率 | −23.0 | −20.0 | −20.5 |
| Qwen3-VL，12.5% | RATE | **−8.5** | −14.6 | −27.6 |
| Qwen3.5，25% | 降分辨率 | −11.0 | −8.5 | −6.3 |
| Qwen3.5，25% | RATE | **−1.2** | −2.6 | −7.4 |
| Qwen3.5，12.5% | 降分辨率 | −24.1 | −20.6 | −19.4 |
| Qwen3.5，12.5% | RATE | **−4.0** | −9.0 | −24.4 |

规律：降分辨率在三组里损失差不多（文字少时略大）；RATE 的损失随文字增多而急剧上升。所以文字少时 RATE 大幅领先，文字多时降分辨率反超。

### 8.3 解读与仍然存在的限制

| 项 | 内容 |
|---|---|
| 和探索阶段对比 | 效应方向完全一致，大小比探索阶段略小（例如 Qwen3-VL 25% 时，≤ 4 个词组的 d 从 −0.136 变成 −0.082）。这是用同一批数据挑选出规律后再在新数据上验证时常见的回归，说明探索阶段的数字有一部分是挑选带来的高估 |
| 可以说的 | 在 TextVQA 上，**图里 OCR 词越少，裁剪越占优；OCR 词很多时，降分辨率占优**。这个规律在没看过的 3500 条数据上、两个模型、两档保留率都成立 |
| 还不能说的 | (1) "OCR 词少"是因为字少，还是因为字小、OCR 没识别出来，仍然区分不了（需要路线 B）；(2) 只在 TextVQA 一个数据集上成立，能否推广到其他场景文字数据集还不知道（需要路线 C）；(3) DocVQA 问题类型那条线索没有做留出确认 |
| 下一步 | 按 §6 的逻辑链，A 成立，可以做 B：下载 TextVQA 的 Rosetta OCR 标注（带文字框），分别按"文字区域总面积"和"单个字的高度"分组 |

### 8.4 对项目的意义（2026-10-22 讨论）

| 项 | 内容 |
|---|---|
| 地位 | 到目前为止最有分量的发现：回答了"裁剪什么时候值得用"，而且给出的是**可以预判的条件**（图里文字的多少），不是"任务 A 好、任务 B 差"这种事后归类 |

## 9. 路线 B：是"字少"还是"字小"（2026-10-22；假设和判读规则在跑分析之前写定）

### 9.1 数据

| 项 | 内容 |
|---|---|
| 标注 | TextVQA 官方 Rosetta OCR v0.2 验证集：`https://dl.fbaipublicfiles.com/textvqa/data/TextVQA_Rosetta_OCR_v0.2_val.json`（textvqa.org/dataset 页面的链接），许可 CC BY 4.0。2026-10-22 下载，9,830,753 字节，MD5 `ca859460b3f8abacdd47483f108613d9`（和服务器的 ETag 一致），SHA-256 `5fe60362…5a02715c`；3166 张图，每个词带相对坐标的文字框 |
| 题目 | TextVQA val 全部 5000 条：第 0–1499 条用 W3 的结果，第 1500–4999 条用 A 的结果；保留 25% 和 12.5% 两档，两个模型 |
| 一致性检查 | 用 image_id 把 OCR 标注和 parquet 对上，并核对两边的 OCR 词表是否一致（不一致的比例要报告出来） |

### 9.2 变量

| 变量 | 定义 | 代表什么 |
|---|---|---|
| n_words | 图里 OCR 词数 | 字少还是字多（H-C4 用的就是它） |
| h_px | 图里 OCR 词框高度的中位数 × 原图高度（像素）。B0 时处理器基本按原图分辨率处理（像素上限是 1677 万） | 字小还是字大 |
| area | 所有 OCR 词框面积之和 ÷ 图片面积 | 文字区域占多大比例（集中还是铺开） |
| h_ans_px（辅助） | 和答案匹配上的 OCR 词，它们框高的中位数（像素）；只在能匹配上的题目子集里有 | 答案那几个字本身大不大 |

### 9.3 假设与判读规则

d = 降分辨率得分 − RATE 得分（负数表示 RATE 好）。对每个"模型 × 保留率"组合，做回归 d ~ z(log h_px) + z(log(1 + n_words))（z 表示标准化），系数的 95% CI 用 bootstrap（1000 次，seed 0）。

| 结果 | 判读 |
|---|---|
| h_px 的系数显著为正（字越大，降分辨率越好），n_words 的系数不显著 | **"字小"解释**：起作用的是文字大小，H-C4 应改写成"小字场景下裁剪更好" |
| n_words 的系数显著为正，h_px 的系数不显著 | **"字少"解释**：H-C4 按原样成立 |
| 两个都显著 | 两者都起作用，比较标准化系数的大小 |
| 两个都不显著 | OCR 特征解释不了，H-C4 只作为经验规律保留 |
| 结论规则 | 4 个组合里有 ≥ 3 个属于同一种情况，才下这个结论；否则写"不一致" |

辅助分析（不参与判定）：两个变量的相关系数（判断共线性）；按 h_px 和 n_words 的中位数切成 2×2 四组，报告每组 d 的均值；用 area 代替 n_words 再跑一遍；在答案匹配上的子集里用 h_ans_px 代替 h_px 再跑一遍。

### 10.2 辅助分析（§9.3 预先列出，不参与判定）

| 分析 | 结果 | 含义 |
|---|---|---|
| 用文字覆盖面积代替词数 | 4 个组合里，**字高的系数都变成约 0 且不显著**（−0.006 到 −0.002），面积的系数显著（+0.066 到 +0.135） | "字小"的作用可以被"文字覆盖面积小"完全吸收。**最简洁的单一描述是：图中文字覆盖的面积越小，裁剪越占优** |

| 没有 OCR 词的图（115 条） | d = −0.119 / −0.254 / −0.174 / −0.295，RATE 大幅占优 | 和"文字越少越占优"一致；也可能是字太小，OCR 根本没识别出来 |

### 10.3 结论

| 项 | 内容 |
|---|---|
| 回答路线 B 的问题 | 不是二选一：字少、字小都起作用，字少的作用更大。用一个变量概括，就是**图中文字覆盖的面积**：面积越小，裁剪越占优；文字铺开时，降分辨率占优 |
| 机制解释（推断） | 文字覆盖面积小时，保留多样性高的 token 足以留住全部文字区域，而且保持原始分辨率；降分辨率则把本来就小的文字整体缩糊。文字铺满时，裁掉一大半 token 必然丢字 |
| 限制 | 仍然只在 TextVQA 一个数据集上；本节分析用的是已经看过的数据（性质是探索性的），"面积"这个概括是辅助分析得到的，需要在别的数据集上确认（路线 C） |

### 13.4 结论

1. **H-C4 在第二个数据集上复现**：按事先锁定的判据 4/4 通过，效应量和 TextVQA 留出数据一致；面积表述也 4/4 成立。
2. **两端都对上了**：文字稀疏的 ST-VQA 上裁剪整体更好（+8–11 分），文字密集的 InfoVQA 上降分辨率整体更好（+9–23 分），而且在 InfoVQA 内部文字面积越大，降分辨率越占优（3/4）。
3. 于是"降分辨率还是裁剪"可以按一个可测量的量来选：**图中文字覆盖面积**。TextVQA、ST-VQA、InfoVQA 三个数据集、两个模型、两档保留率方向一致。
4. 边界：两个自然场景文字数据集 + 一个信息图数据集；只比较了修正版 RATE 和降分辨率；只测了 4B 模型和 25% / 12.5% 两档；ST-VQA 可能在训练数据里出现过（B0 0.71，没有天花板）。
