# W3 精度扫描方案（预注册，2026-10-20，开跑前定稿）

## 1. 设置

| 项 | 取值 | 理由 |
|---|---|---|
| 服务参数 | 和 W1 精度评测完全相同：gpu-memory-utilization 0.90、max-model-len 32768、max-num-seqs 64、图像尺寸用模型默认值、关闭思考、greedy、seed 0 | 可以直接复用 W1 的逐样本结果作为 B0（按 doc_id 配对），不必重跑 |
| 插件 | `vts_plugin` 0.1.0，每次运行前从 release 目录安装 | — |
| 任务与子集 | ChartQA test 全量 2500；MME 全量 2374；TextVQA val 前 1500 条；DocVQA val 前 1000 条；MMBench-EN dev（规则打分）前 1500 条 | 控制 GPU 时间；各配置用同一批样本，做配对比较 |
| 评测客户端 | lmms-eval 0.7.3，OpenAI 接口，并发 32 | 和 W1 一致 |

## 2. 配置（每个模型都跑）

| 批次 | 方法 | 保留率 | 种子 | 运行次数 |
|---|---|---|---|---|
| A（先跑） | random、divprune、rate、downsample | 0.25 | 0 | 4 |
| A | pool2x2 | ≈ 0.25（固定） | — | 1 |
| A | rate_pr（PR 原样，只做参考） | 0.25 | 0 | 1 |
| A | random | 0.25 | 1、2 | 2 |
| B | random、divprune、rate、downsample | 0.5、0.125 | 0 | 8 |

合计每个模型 16 次，两个模型 32 次。按 W1 的单价估算（一个模型跑全量约 1.8 GPU·时，这次子集约占全量的 45%），总共约 **19 GPU·时**，A、B 两批各约 9.5 GPU·时，都需要独占 GPU0。

## 3. 分析（预注册）

| 指标 | 怎么算 |
|---|---|
| 每个任务的精度 | 和 W1 的指标相同（relaxed acc / exact match / ANLS / MME 分数 / MMBench 规则打分） |
| 精度变化 Δ | 和 B0 按样本配对相减；ChartQA、TextVQA、DocVQA、MMBench 给配对 bootstrap 95% CI（2000 次，seed 0）；MME 是汇总分数，只报点估计 |
| 实际视觉 token 数 | lmms-eval 记录的每样本 input_tokens 的均值，和 B0 相比的比例。降分辨率受处理器最小像素数（65,536，相当于 64 个 token）的下限限制，所以它的实际比例要单独报告 |
| 随机方法的波动 | 保留率 0.25 时，3 个种子的极差 |
| 汇总 | OCR 类（ChartQA、TextVQA、DocVQA）的平均 Δ，通用类（MMBench、MME 归一化后）的平均 Δ，分开报告 |

**判断规则（事先定好）**：

| 规则 | 用途 |
|---|---|
| 保留 25% 时，最好的方法在 OCR 类上的平均 Δ 掉了超过 3 pt | 按预案，W4 的主保留率改用 50% |
| 某方法的 Δ 置信区间和另一方法的不重叠 | 才说"更好"或"更差"；重叠就写"无法区分" |
| 降分辨率在某个保留率下，Δ 不比最好的裁剪方法差（CI 重叠或更好） | 在该保留率下支持 H2 的前半部分（精度侧）；速度侧要等 W4 |
| Qwen3.5 的 MMBench | 已知 13.7% 的回答格式不合规，只做同模型配对比较，不和 Qwen3-VL 横向对比 |

## 4. 风险

| 风险 | 应对 |
|---|---|
| 子集取前 N 条，题型可能不均衡 | **已检查（2026-10-20）**：MMBench 前 1500 条覆盖全部 20 个类别，单类占比偏差 ≤ 4 pp；DocVQA 前 1000 条的主要题型占比接近全集（表格/列表 26% 对 28%，版面 28% 对 25%，自由文本 15% 对 10%），组合标签覆盖 27/55 种；ChartQA 用全集。TextVQA 没有类别字段 |
| GPU0 被占 | 每次运行前检查，被占就退出，不会挤进去 |
| T5（HF 交叉检验）没通过 | T5b 已通过（2026-10-20），可以开跑 |
