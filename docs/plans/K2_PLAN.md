# W4.5 K2：多轮带图会话的前缀缓存容量（预注册，2026-10-25）

> 分两段预注册：§1–§4 写于任何 K2 运行之前；§5 的数值预测在 B0 标定跑完、压缩配置一次都没跑之前锁定（和 W4 K1 的做法一样）。"不一致时怎么处理"沿用 `docs/plans/FOLLOWUP2_PLAN.md` 开头的统一规则。

## 1. 问题

视觉 token 压缩能省 KV 显存。在多轮会话里，省下的显存表现为：前缀缓存能同时留住更多会话的图片。会话数比缓存能装的多时，前缀缓存会被挤掉，后面的轮次就要重算图片，首字延迟变长。原假设 H-K2："压缩换来的命中率提升，全注意力更大"。

读 vLLM 0.32 源码得到的两个事实（`v1/core/single_type_kv_cache_manager.py`，约 1415–1460 行）：
- 混合模型（Qwen3.5）开前缀缓存时用 align 模式，前缀命中按调度块大小（528 个 token）对齐；
- align 模式会清掉请求中间的 Mamba 状态，只保留够得着的边界状态，所以缓存一个会话前缀时，Mamba 状态的开销大致固定，不随长度增长。

（2026-10-27 补注：这一机制已由 vllm-project/vllm#45238 报告过，写方案时没有引用。）

由此得到一个事先说不准的风险：压缩后一个会话的前缀可能不足 528 个 token，混合模型就可能完全命不中。所以先用 B0 标定。

## 2. 负载

- **会话**：第 1 轮是 1 张 896×896 合成噪声图（每个会话不同）加一句文字；第 2–4 轮各一句文字追问。每轮输出 64 个 token（ignore_eos，temperature 0，关闭思考）。历史里带上模型真实生成的回复，并且每轮都重新发送图片（OpenAI chat 格式）。
- **调度**：S 个会话轮转，先把所有会话的第 t 轮发完，再发第 t+1 轮；同时在途的请求最多 8 个。同一个会话相邻两轮之间，夹着其他 S − 1 个会话的请求。
- **会话数** S ∈ {8, 16, 24, 32, 48, 64, 96, 128}（标定用；正式网格见 §3）。每个点用全新的会话（图片和文字都不同），点和点之间不会互相命中。
- **服务**：和 K1 相同的显存预算（`--kv-cache-memory-bytes` 4 GiB），`max-model-len` 4096，`max-num-seqs` 128，前缀缓存开（默认），`--enable-prompt-tokens-details`。
- **指标**：第 2–4 轮的缓存命中率 = 命中的 token 数 ÷ prompt token 数（每个请求由服务端返回）；第 2–4 轮首字延迟的中位数；有命中的请求占比（命中的 token 数 > 0）。（写方案时原定的"图片被留住的比例"在混合模型上没法算：命中按 528 对齐，图片整个在缓存里也可能只报 528 个命中 token。运行前改成现在的口径。）
- **实现**：客户端 `experiments/w6/k2_client.py`（离线测试 `tests/test_k2_client.py`），运行 `experiments/w6/run_k2.sh`，汇总 `experiments/w6/k2_summary.py`。命中率按 token 求和后相除。

## 3. 运行

1. **标定**：B0，两个模型，S 全部 8 档，1 次。用来测：命中的粒度（混合模型是否按 528 对齐）、每个会话在缓存里的占用、容量阈值 S*。
2. **锁定预测**（§5）：只用标定数据和记账模型，写下压缩配置的预测，提交后再跑正式。
3. **正式**：{B0、降分辨率 50%、随机 50%} × 两个模型 × S 共 15 档 × 2 次。
- 估计时长（推断）：标定约 20 分钟（实际 16 分钟），正式约 2.6 小时。
- **正式网格（标定后、压缩配置运行前改定）**：S ∈ {8, 16, 20, 24, 28, 32, 36, 40, 44, 48, 56, 64, 72, 80, 96}。原因：标定显示命中率在 8 个会话以内从满命中掉到 0（全注意力在 24 → 32 之间，混合在 48 → 64 之间），原来的 8 档网格太粗，S\* 的插值主要由网格决定。去掉 128（标定时两个模型都是 0）。

**容量阈值 S\* 的定义**：第 2–4 轮命中率降到 S = 8 时命中率的一半所对应的会话数，在相邻两档之间线性插值。

## 4. 预注册的假设（判据先写死，数值在 §5 锁定）

| 假设 | 判据 |
|---|---|
| **H-K2a**（原 H-K2）压缩换来的容量提升，全注意力更大 | 容量提升 S\*(压缩) ÷ S\*(B0)：全注意力比混合注意力大 ≥ 10%（相对） |
| **H-K2b** 记账模型能预测容量提升 | 每个模型、每种方法，实测 S\* 在 §5 预测值的 ±20% 以内 |
| **H-K2d**（标定后、压缩运行前加入）混合模型上压缩会降低小 S 时的命中率 | 6 个配置在 S = 8 时的第 2–4 轮命中率，都在 §5 预测值的 ±5 个百分点以内（预测：Qwen3.5 B0 53.1%，压缩后约 29%；Qwen3-VL 三个配置 94–96%） |
| **H-K2c** 停止判据（预先写下的） | Qwen3.5 的 B0 在 S = 8 时，第 2–4 轮命中率 ≥ 20%；不满足就把 K2 降级为只在全注意力模型上演示 |

## 5. 锁定的预测（标定后、正式运行前填写）

写于 2026-10-26，B0 标定之后，任何压缩配置运行之前。计算脚本 `experiments/w6/k2_predict.py`（`--json` 输出给 `k2_summary.py --pred`）。

### 5.1 标定结果（B0，1 次，原 8 档网格）

| 模型 | KV 池 | 第 1–4 轮 prompt token | 命中时每轮命中 token | S = 8 命中率 | 命中率随 S（8 / 16 / 24 / 32 / 48 / 64） | S\* |
|---|---|---|---|---|---|---|
| Qwen3-VL | 1820 块 × 16 | 812 / 901 / 990 / 1079 | 864 / 960 / 1040 | 96.5% | 96.5 / 96.5 / 96.5 / 21.7 / 0 / 0 | 29.2 |
| Qwen3.5 | 248 块 × 528 | 816 / 905 / 994 / 1083 | 528 / 528 / 528 | 53.2% | 53.2 / 53.2 / 53.1 / 47.6 / 26.2 / 0 | 47.7 |

- H-K2c 成立（53.2% ≥ 20%），K2 不降级。
- 两个观察：全注意力每轮命中整个上一轮（含回复，按 16 对齐）；混合模型每轮只命中 528 个 token（按调度块对齐，上一轮的回复渲染时去掉了思考标签，共同前缀 < 1056）。
- 首字延迟（命中时 / 不命中时，中位数）：Qwen3-VL 约 200 / 800 ms，Qwen3.5 约 370–540 / 930 ms。

### 5.2 记账模型

会话 s 的第 t+1 轮能命中，当且仅当缓存还装得下全部 S 个会话第 t 轮之后的块：S × B_t ≤ C − O。

- 全注意力：B_t = ⌊(P_t + 64) / 16⌋，命中 16 × B_t 个 token。
- 混合：B_t = 4 × ⌊(P_t + 64) / 528⌋（每个完整调度块 1 个注意力块 + 3 个 GDN 状态块），命中 ⌊(P_t − 5) / 528⌋ × 528 个 token（下一轮重新渲染时去掉约 5 个思考标签 token）。
- O 是 8 个在途请求在缓存之外占的块，每个模型用标定拟合一次后固定：Qwen3-VL 第 2 轮的台阶在 S = 32 处还有 81% 的会话命中，取 S_max ≈ 32.5，得 O = 1820 − 54 × 32.5 ≈ 65；Qwen3.5 第 3 轮的台阶在 S = 48 处有 48% 命中，取 S_max ≈ 48，得 O = 248 − 4 × 48 = 56。
- 视觉 token：B0 784，降分辨率 50% 400（640×640），裁剪 50% 392。
- **记账模型在标定上的不足（照实记录）**：Qwen3.5 第 4 轮的台阶，记账预测在 S = 24（B_3 = 8），实测 S = 32 时还有 69% 命中。这一步不影响 S\*，因为 S\* 落在第 2、3 轮的台阶上。

### 5.3 锁定的预测（正式网格上的插值 S\*）

| 模型 | 方法 | 每轮 S_max（第 2 / 3 / 4 轮） | S = 8 命中率 | 预测 S\* | 预测容量提升 |
|---|---|---|---|---|---|
| Qwen3-VL | B0 | 32.5 / 29.2 / 27.0 | 96.4% | 29.6 | 1 |
| | 降分辨率 50% | 58.5 / 48.8 / 42.8 | 94.2% | 50.8 | **1.71×** |
| | 随机 50% | 58.5 / 50.1 / 42.8 | 94.5% | 50.7 | **1.71×** |
| Qwen3.5 | B0 | 48 / 48 / 24 | 53.1% | 50.0 | 1 |
| | 降分辨率 50% | 不命中 / 不命中 / 48 | 28.9% | 52.0 | **1.04×** |
| | 随机 50% | 不命中 / 不命中 / 48 | 29.2% | 52.0 | **1.04×** |

- 按这组预测，H-K2a 成立（1.71 对 1.04）。机制：混合模型的命中按 528 对齐，压缩后第 1–3 轮的共同前缀都不足 528，只有第 4 轮能命中，所以小 S 时命中率从 53% 掉到约 29%（H-K2d）；它能装下的会话数由"每个 528 块占 4 个池块"决定，压缩前后都只用 1 个完整块，容量几乎不变。
- 风险（推断）：混合压缩配置的第 3 轮共同前缀约 516 个 token，离 528 只差 12 个；如果实际文字 token 数比标定多 12 个以上，第 3 轮也会命中，S = 8 命中率会升到约 58%。
