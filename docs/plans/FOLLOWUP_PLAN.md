## S1：K1 记账模型换条件再测

**问题**：W4 K1 的核心结论（显存受限时，token 减半给混合注意力带来的并发提升只有全注意力的约七成）只在保留 50%、896×896、2 张图这一个条件下测过。记账模型能不能在没见过的条件下同样准确地预测？

**设置**：和 K1 完全相同（4 GiB KV 预算、每个请求 2 张图、输出 256、max_num_seqs 128），只改条件。方法用随机（代表裁剪，K1 里三种裁剪相差 ≤ 1.4%）和降分辨率，加上 B0；并发 128；3 次重复。
- S1a：保留 25%，896×896；
- S1b：保留 50%，1344×1344（每张图 1764 个视觉 token；B0 每个请求约 3600 个 prompt token，`max-model-len` 4096 够用）。

**锁定的预测**（`k1_predict.py --m 1`，文本 token 数沿用 W4 的标定：Qwen3-VL `--text 76`，Qwen3.5 `--text 80`；这套参数在保留 50%、896 时正好给出当时锁定的 1.79 / 1.33）：

| 条件 | 全注意力：裁剪 / 降分辨率 | 混合：裁剪 / 降分辨率 | 结构相对差距（裁剪） |
|---|---|---|---|
| S1a 保留 25%，896 | 2.947 / 2.947 | 1.464 / 1.464 | 50% |
| S1b 保留 50%，1344 | 1.893 / 1.859 | 1.522 / 1.502 | 20% |

**假设和判据**（主指标：并发 128 时的稳态运行并发增益，按次和同一轮 B0 配对后取平均，同 K1）：

| 假设 | 判据（违反即证伪） |
|---|---|
| H-S1a 记账模型在新条件下仍准 | 8 个格子（2 个条件 × 2 个模型 × 2 种方法）里，实测 ÷ 预测都在 [0.85, 1.15] |
| H-S1b 结构差距随条件变化的方向符合预测 | S1a 的相对差距 ≥ 40%；S1b 的相对差距在 [10%, 30%] |
| H-S1c 同样的 token 数，降分辨率和裁剪的并发增益相同 | 两者相差 ≤ 10%（每个条件、每个模型） |

## S2：FP8 叠加小于相乘的 Amdahl 解释

**问题**：W5c 否定了"FP8 下 ViT 变慢"这个解释。剩下的备选解释是 Amdahl 比例：FP8 只加速 LLM 部分，裁剪不减少 ViT，所以 FP8 对裁剪配置的加速比天然更小。另外 W5c 推断"serving 时一次 ViT 调用处理多个请求的图片，FP8 的量化开销被摊薄"，也还没验证。

**设置**：P 负载（4 张 896×896 图、输出 32），预算 2048，并发 64，打开 ViT 追踪（`VTS_VIT_TRACE`，每次调用前后同步 GPU），{B0, RATE 50%} × {bf16、全量 FP8、只量化 LLM}，两个模型，1 次重复。追踪会让吞吐略降，所以 R 用 W5c c2 的不追踪结果，追踪只用来测时间占比和批组成。

**定义**：
- 每个请求的 GPU 时间 T = 1 / 吞吐（饱和时 GPU 串行工作）；
- 每个请求的 ViT 时间 V = 测量窗口内 ViT 调用总耗时 ÷ 完成的请求数；
- 非 ViT 时间 L = T − V。T 和 V 都取自同一个追踪运行；
- Amdahl 预测：只量化 LLM 时，ViT 不受影响，LLM 部分的加速倍数 s 取自 B0（s = L_bf16(B0) ÷ L_fp8l(B0)），并假设对 RATE 配置也一样。于是
  T_pred(只量化 LLM + RATE) = V_fp8l(RATE) + L_bf16(RATE) ÷ s，
  R_pred = T_fp8l(B0) × T_bf16(RATE) ÷ [T_pred × T_bf16(B0)]（即 R = g(FP8 + RATE) ÷ [g(FP8) × g(RATE)]，各 g 都相对同一轮 bf16 B0），
  实测 R 用同样的式子把 T_pred 换成实测的 T_fp8l(RATE)。都取自追踪运行。（2026-10-24 正式运行前更正：初稿里 R_pred 的式子多乘了一个 g(RATE)。）

**假设和判据**：

| 假设 | 判据（违反即证伪） | 预测 |
|---|---|---|
| H-S2a serving 时一次 ViT 调用处理多个请求 | 并发 64 时每次 ViT 调用的平均图片数 ≥ 8（两个模型、B0 bf16） | 8–16 张 |
| H-S2b 批处理下 FP8 的 ViT 不慢 | 全量 FP8 时每张图的 ViT 时间 ≤ bf16 的 1.05 倍（B0，两个模型） | 和 bf16 持平或更快 |
| H-S2c Amdahl 能解释只量化 LLM 时的 R | 追踪运行里 \|R_pred − R_实测\| ≤ 0.03（两个模型） | 两者接近 |

## S3：Qwen3.5 的进程历史效应

**问题**：W4 ⑥c 发现，同一进程里先跑过 4 图请求（P）后，Qwen3.5 的单图请求（D）prefill 慢约 14 ms（88.5 对 74.8 ms，3 对 3 个进程），机制未知。备选解释之一是前缀缓存里留下的 Mamba 状态块 / KV 块。

**设置**：沿用 ⑥c（`run_proc_rep.sh`，stage_bench 单请求，20 次中位数），Qwen3.5 B0。前缀缓存关、开各做"只跑 D"和"先 P 后 D"，各 2 个进程，交替启动；开的那组是阳性对照。

| 假设 | 判据 | 读法 |
|---|---|---|
| H-S3a 阳性对照：缓存开时效应复现 | 先 P 后 D 比只跑 D 慢 ≥ 8 ms（两组进程的中位数之差） | 不复现则这次实验不能判 S3b |
| H-S3b 缓存关时效应消失 | 两者相差 ≤ 3 ms | 成立 → 与前缀缓存有关；仍 ≥ 8 ms → 与前缀缓存无关 |

## S4：B0 在并发 64 时比并发 32 还慢

**问题**：W4 ③ 里 B0 在 P 负载、预算 2048 时，并发 64 的吞吐比并发 32 低（Qwen3-VL 1.91 对 1.95，Qwen3.5 1.99 对 2.10），让裁剪的实测增益超过了预测上界，原因没查。一个备选解释是编码器缓存装不下时同一张图被重复编码（等待的请求多了，编码结果在被使用前被挤掉）。

**设置**：B0，P 负载，预算 2048，并发 {32, 48, 64, 96}，2 次重复；打开 ViT 追踪和调度指标采样（运行数、等待数、KV 占用、抢占次数）。

| 假设 | 判据 |
|---|---|
| H-S4a 现象复现 | 并发 64 的吞吐低于并发 32（两个模型，2 次都是） |
| H-S4b 重复编码 | 每个请求被编码的图片数：并发 64 比并发 32 多 ≥ 5%（并发 32 时应接近 4.0） |

H-S4b 证伪时，只报告调度指标里看到的差别（探索性，不下因果结论）。
