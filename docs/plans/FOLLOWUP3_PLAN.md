# 补充实验 U1：高负载下 GPU 变慢是不是降频（预注册，2026-10-25，写于运行之前）

> FOLLOWUP2_RESULTS §6 的三个后续里只做第 1 个。不改插件、不重装（沿用 0.1.7）。
> 脚本：`experiments/w6/run_followups3.sh`。"不一致时怎么处理"沿用 `docs/plans/FOLLOWUP2_PLAN.md` 开头的统一规则。

**问题**：T1 显示 B0 并发越高，每步 GPU 执行越慢（ViT 每张图 36.5 → 39.0 ms）；T2 显示 bf16 的 ViT 从并发 1 到并发 64 慢了 22%，FP8 基本不变。共同的备选解释是持续高负载时 GPU 降频（L40 功耗上限 300 W，最高 SM 时钟 2490 MHz），而且对 bf16 的影响更大。

**设置**：serving，P 负载（4 张 896 图、输出 32），预算 2048；B0 × {bf16，全量 FP8}；并发 {1, 32, 96}；两个模型；1 次。打开 ViT 追踪；`nvidia-smi dmon -s pucv` 每秒记录功耗、温度、SM 时钟（pclk）、显存时钟、利用率、功耗降频占比（pviol）。每个测量点只取 bench 开始到结束这段时间。

**假设和判据**

| 假设 | 判据（违反即证伪） | 预测 |
|---|---|---|
| **H-U1a** 高负载下降频 | bf16：并发 96 的平均 SM 时钟比并发 1 低 ≥ 5%（两个模型） | 成立，伴随 pviol > 0 |
| **H-U1b** bf16 的 ViT 变慢是降频造成的 | bf16：ViT 每张图的时间比（96 ÷ 1）和 SM 时钟比的倒数（时钟 1 ÷ 时钟 96）相差 ≤ 5%（两个模型） | 两者接近 |
| **H-U1c** FP8 受影响更小是因为它降频更少 | 并发 96 时 FP8 的平均 SM 时钟比 bf16 高 ≥ 3%（两个模型） | 成立（FP8 的 GEMM 功耗更低，推测） |

读法：
- U1a 证伪 → 不是降频，回到"显存驻留数据变多导致访存效率下降"等其他备选解释，写成新假设，不在本轮追加。
- U1a 成立、U1b 证伪 → 降频存在，但解释不了 ViT 变慢的幅度。
- U1c 证伪 → FP8 不变慢的原因不是时钟。

**估计时长**：8 个服务（2 个模型 × 2 种精度 × 1 次，每个服务跑 3 档并发），约 30 分钟。
