> W5(a)(b) 都做，完整版（约 8 小时），只用 GPU0；插件 0.1.5 重装进 vts 环境。FP8 用 vLLM 在线量化（`--quantization fp8`），不下载新模型。
> 下面的预测和判据写于正式运行之前。**例外**：(a) 的算子微基准在开发时已经试跑过（每格 10 次，见 §1.1），所以算子本身的加速比不作为预注册假设，只作为记录。

## 1. W5(a)：DivPrune 选择的 Triton 实现

**动机**：W4 ① 里 DivPrune 每张图选择约 25 ms（4 张图约 100 ms），和整个 ViT 差不多，是它在 P 负载上吞吐增益最低（1.31× / 1.32×，随机 1.57× / 1.60×）的唯一原因（W4_RESULTS §5.4 第 2 条）。PyTorch 版是 k 步互相依赖的循环，每步一次 GEMV 加一次 argmax，约 4 个小 kernel，784 个 token、保留 50% 时约 1600 次 kernel 启动，受启动开销限制。

**实现**（`src/vts_plugin/divprune_triton.py`，插件 0.1.5，`VTS_DIVPRUNE_IMPL=triton`，默认仍是 torch）：
1. 一次 GEMM 算出 S = x xᵀ（fp32，x 为 L2 归一化后的特征）；
2. 第一个点和 PyTorch 版相同（最近邻距离最大的 token），结果留在 GPU 上，不做主机同步；
3. 剩下的 k − 1 步在**一个** Triton program 里完成：到已选集合的最小距离留在寄存器里，每步读 S 的一行（在 L2 里），取 argmax（平局取第一个）。
N > 4096 时退回 PyTorch 版（S 需要 N² × 4 字节）。

**正确性**（`tests/test_vts_divprune_triton.py`，GPU0 上 60 项全部通过）：
- 在同一个 S 上，kernel 的选择序列和纯 PyTorch 循环**逐位一致**（6 种形状 × 2 种分布 × 3 档保留率）；
- 和原来的 `divprune_indices` 比：float64 下的贪心证书（每一步选中的 token 都是离已选集合最远的，容差 1e-4）全部成立，两个保留集合的 Jaccard ≥ 0.9；
- 负对照：随机选择和"每步取最近的"都违反证书（违反步数 > k/2）；
- 路由：`select(..., divprune_impl="triton")` 确实走了 kernel（计数器），CPU 输入和 N > 4096 时退回 PyTorch。

## 2. W5(b)：FP8 权重和 token 压缩能否叠加

**问题**：权重量化（省 GEMM 计算和权重带宽）和视觉 token 压缩（省 token 数）作用在不同的维度上，收益是不是相乘、精度损失是不是相加。这是部署时会直接问到的问题。

**设置**：`vllm serve --quantization fp8`（在线把 BF16 权重量化成 FP8，激活动态量化；L40 是 Ada，支持 FP8 tensor core）。方法：B0、降分辨率 50%、修正版 RATE 50%（降序变体，和 W4 一致），各有 bf16 和 fp8 两个版本，同一轮交替运行。负载和 W4 相同：P（4 张图、输出 32、预算 2048）和 D（1 张图、输出 512），并发 1 和 64，3 次重复。精度：3 个 OCR 任务（ChartQA 全部、TextVQA 前 1500、DocVQA 前 1000），bf16 的对照用 W1 B0 和 W3 的结果。另外用分阶段计时（b1）看 FP8 下 ViT 和 LLM 各快了多少：vLLM 是否也把视觉编码器量化了，事先不确定，只记录。

### 2.1 预注册假设（b）

记 g(x) = x 的吞吐 ÷ 同一轮 bf16 B0 的吞吐（按次配对，取中位数），Δ(x) = x 的精度 − bf16 B0。

| 假设 | 判据（违反即证伪） | 预测 |
|---|---|---|
| **H-F0** FP8 本身几乎不掉精度 | \|Δ(fp8 B0) 的 OCR 平均\| ≤ 1.5 分（两个模型） | 掉 0–1 分 |
| **H-F1** FP8 本身有速度收益 | P 并发 64：g(fp8 B0) ≥ 1.10；D 并发 1：TPOT 改善 ≥ 15% | P 1.2–1.5×；D 并发 1 改善 25–40% |
| **H-F2** 吞吐收益相乘 | P 并发 64：R = g(fp8 + m) ÷ [g(fp8 B0) × g(m)] 在 [0.90, 1.10]，m ∈ {降分辨率, RATE}，两个模型 | R 在 0.85–1.0，更可能略低于 1（FP8 省不掉 CPU 预处理和调度这些固定开销） |
| **H-F3** 精度损失相加 | OCR 平均：Δ(fp8 + m) − Δ(fp8 B0) − Δ(m) 在 ±1.5 分以内 | 在 ±1 分以内 |

D 负载并发 64 的结果只报告，不设假设。

## 3. 运行

- 脚本：`experiments/w5/run_w5.sh`，按顺序跑 9 个阶段：a1 GPU 测试 → a2 算子微基准（30 次）→ a3 分阶段计时 → a4 P serving → a5 ChartQA 精度 → b1 FP8 分阶段计时 → b2 P serving → b3 D serving → b4 OCR 精度。一个阶段失败会记录下来，后面的阶段继续跑；每个服务启动前都检查 GPU0 上没有别的进程。
- 冒烟：`SMOKE=1`（方法减少、1 次重复、并发 8、每个任务 10 条，跳过 b3），约 30 分钟。
- 估计时长（推断，按 W4 的实际耗时）：a 约 1.5 小时，b2 约 2 小时，b3 约 2.8 小时，b4 约 1.7 小时，合计约 8 小时。
- 汇总：serving 用 `experiments/w4/serve_summary.py`（fp8 配置的方法名带 `fp8` 前缀，和 bf16 B0 配对）；精度用 `experiments/w3/summarize_w3.py`。

## 4. 停止判据

- FP8 在某个模型上起不来（例如 Qwen3.5 的线性注意力层不支持）：记录原因，b 部分只报告能起来的模型，不换别的量化方案。
- a 阶段任何一项正确性测试失败：停止 a4 和 a5（不能用错的 kernel 测吞吐），b 部分照常运行。

## 5. W5c：FP8 只量化语言模型（ViT 保持 bf16）的对照（预注册，2026-10-24，写于运行之前）

**问题**：W5(b) 里裁剪 + FP8 的吞吐只有相乘预期的 0.84–0.92（H-F2 证伪）。备选解释有两部分：
1. **ViT 变慢**：vLLM 的在线 FP8 把 ViT 也量化了，ViT 反而慢 10–13%（4 张图）/ 55–69%（1 张图），裁剪省不掉 ViT；
2. **Amdahl 比例**：即使 ViT 不变慢，FP8 只加速 LLM 部分。裁剪后 LLM 的占比变小、ViT 的占比变大，所以 FP8 对裁剪配置的加速比天然比不压缩时小，R < 1。

让 FP8 跳过视觉编码器，可以去掉第 1 部分，保留第 2 部分，从而把两者分开。

**设置**：`--quantization fp8_per_tensor --quantization-config '{"ignore": ["visual.*"]}'`（vLLM 0.32 的在线量化支持 fnmatch 风格的忽略列表；两个模型的视觉编码器前缀都是 `visual`）。冒烟时核对两点：语言模型线性层的量化方式和 W5 的 `--quantization fp8` 相同（`fp8_per_tensor_static`），被量化的层数少了 ViT 那部分。同一轮里重跑 bf16 和全量 FP8 作对照。

- c1 分阶段计时：B0 × {bf16, 全量 FP8, 只量化 LLM}，两个模型，20 次中位数；
- c2 P 负载（预算 2048，并发 1 / 64，3 次重复）：{B0, 降分辨率, RATE} × bf16，{B0, RATE} × 全量 FP8，{B0, 降分辨率, RATE} × 只量化 LLM；
- c3 精度：只量化 LLM 的 B0，ChartQA 2500 条，两个模型。
- 预计约 3 小时（推断）。

**预注册假设**（R 的定义同 §2.1；"同一轮"指 c2 内部）

| 假设 | 判据（违反即证伪） | 预测 |
|---|---|---|
| **H-V1** ViT 不再变慢 | c1：只量化 LLM 时 ViT 时间在同一轮 bf16 的 ±5% 以内（两种形状、两个模型） | 和 bf16 相同 |
| **H-V2** ViT 变慢是 R < 1 的一部分原因 | P 并发 64：R(只量化 LLM + RATE) − R(全量 FP8 + RATE) ≥ +0.03（两个模型） | 提高 0.03–0.08 |
| **H-V3** Amdahl 部分仍在 | P 并发 64：R(只量化 LLM + RATE) < 0.97（两个模型） | Qwen3-VL 0.93–0.97，Qwen3.5 0.88–0.93 |
| **H-V4** 只量化 LLM 不比全量 FP8 慢 | P 并发 64：g(只量化 LLM 的 B0) ≥ g(全量 FP8 的 B0) | 高 2–8% |
| **H-V5** 精度不变 | c3：ChartQA \|Δ\| ≤ 1.0（相对 bf16 B0） | 和全量 FP8 一样不掉分 |

H-V2 成立、H-V3 成立 → 两部分都存在。H-V2 证伪 → ViT 变慢不是原因，W5_RESULTS §2.5 第 3 条的解释要改写。H-V3 证伪（R 回到 ≥ 0.97）→ 主要是 ViT 变慢，Amdahl 部分可以忽略。
